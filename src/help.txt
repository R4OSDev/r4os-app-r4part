R4PART - partition and volume maintenance

LIST DISK | LIST PARTITION | LIST VOLUME
SELECT DISK <number> | SELECT PARTITION <number> | SELECT VOLUME <number|letter>
DETAIL [DISK|PARTITION|VOLUME] | RESCAN

CREATE PARTITION PRIMARY|EFI|BIOS [SIZE=MB] [OFFSET=KB] [TYPE=id] [ID=guid] [NAME="name"]
DELETE PARTITION
CLEAN [ALL]
CONVERT GPT|MBR [ID=guid-or-hex]
FORMAT FS=NTFS|FAT32 [QUICK|FULL] [LABEL="label"]
EXTEND [SIZE=MB]
SHRINK QUERYMAX | SHRINK [DESIRED=MB]
ASSIGN [LETTER=X] | REMOVE [LETTER=X]
OFFLINE [DISK|PARTITION|VOLUME] | ONLINE [DISK|PARTITION|VOLUME] [LETTER=X]
SET ID=guid-or-MBR-hex-type
ATTRIBUTES GPT [SET=0xmask] [CLEAR=0xmask]
UNIQUEID DISK|PARTITION [ID=guid-or-disk-hex]
ACTIVE | INACTIVE
CHECK GPT | REPAIR GPT
HELP | EXIT

SIZE and DESIRED use MB (1024 KB), OFFSET uses KB. New starts must align to 1 MB.
Without SIZE, CREATE uses the remainder of the selected free range.
Without OFFSET, CREATE chooses the first sufficiently large free range.
GPT TYPE is a GUID; MBR TYPE is a hexadecimal byte. CREATE defaults to basic
GPT data or MBR type 07. EFI/BIOS require GPT. CONVERT requires an empty table.
FAT32 requires at least 65525 clusters. NTFS uses 4096-byte clusters and a
bounded metadata buffer. FULL is the FORMAT default; QUICK keeps free data.

EXTEND adds SIZE MB (or all complete free MB) immediately after an NTFS
partition; its first sector and IDs stay fixed. Clean NTFS 3.1 with 512-byte
sectors, 4-KB clusters, 1-KB records and 4-KB indexes is supported. Metadata
attribute lists, real bad clusters and oversized root indexes are rejected.
The new area must also fit the relocated bitmap. Open files cause Busy.
An interrupted resize can require offline NTFS/table repair; no automatic
rollback is promised. A successfully resized mount keeps its former letter.

SHRINK QUERYMAX reads the actual cluster bitmap and MFT runlists. File data
and other metadata remain fixed; only the bitmap may move. The highest fixed
allocation, real bitmap relocation space and a 16-MB floor set the limit.
SHRINK removes DESIRED MB, or the reported maximum when omitted. Requests
above that limit fail before confirmation. A busy target cannot be resized.
The smaller filesystem is flushed and verified before its partition shrinks.
Attribute lists and more than 1,048,576 MFT records are unsupported for resize;
allocated extents must agree with the bitmap. No complete partition move.

Mutations show the exact target and require YES DISK n [PARTITION n].
No forced overwrite of busy, running or reserved volumes is supported.
Wrong geometry, unknown options and unsupported conversions stop before I/O.
Ctrl+C cancels input or an active operation; after writing began, the target
may be partially changed. Read the reported flush/verification status.

ASSIGN mounts an unmounted partition; use REMOVE before changing its letter.
C: and Recovery R: are reserved. OFFLINE flushes and unmounts the selected
disk/partition through exclusive storage admission. This shared mount state
remains after EXIT. ONLINE mounts the selected partition or all supported
partitions of a disk; ASSIGN chooses a particular letter. It does not power
down a device or prevent another explicit mount operation.
RESCAN refreshes the selected disk. Device replacement clears the selection.
Changed identifiers require boot installation mappings to be revalidated.

R4PART uses the current Terminal/SSH console. EXIT returns to its caller.
R4PART LIST DISK and R4PART /? also work as one-command invocations.

CHECK GPT reports the primary header/array and backup independently, including
CRCs, ranges, unique IDs and overlaps. It succeeds only when both agree.
REPAIR GPT is a no-op on a healthy table. Otherwise it restores just the bad
copy from one intact, matching counterpart, with explicit whole-disk consent.
It preserves the good copy, protective MBR and partition payload. Both invalid,
conflicting copies, hybrid MBR, I/O ambiguity and unsupported layouts refuse.
Repair supports GPT 1.0/92-byte headers, 128-byte entries, at most 128 entries,
512-byte sectors and a backup at the actual end of the disk. It cannot repair
filesystems or adapt a raw USB clone to different media capacity.

R4PART /S "C:\TEMP\PART.TXT"
Loads the whole UTF-8 (optional BOM) script before executing; maximum 64 KB,
512 bytes per line. CRLF/LF, empty lines and REM comments are supported.
Commands have exactly the interactive syntax. Each destructive command must
be followed by its full YES DISK n [PARTITION n] line. Empty/comment lines
may intervene. EOF, wrong confirmation, invalid selection or any other error
stops immediately with exit code 1. Success/EXIT returns 0. There is no NOERR,
implicit YES, variable expansion or automatic rollback of earlier commands.
A script's own volume can be affected because its file is already in RAM.
Ctrl+C and caller shutdown still cancel; a failed SELECT clears old selection.

Example read-only script (replace disk 1 with your actual LIST DISK selection):
  REM inspect a selected GPT disk
  SELECT DISK 1
  DETAIL DISK
  CHECK GPT
  LIST PARTITION
  EXIT

Example creating one partition in free space (review disk number first):
  SELECT DISK 1
  CREATE PARTITION PRIMARY SIZE=64 NAME="Tools"
  YES DISK 1
  REM CREATE selects the new partition; determine its number in LIST PARTITION
  LIST PARTITION
  EXIT
Then use FORMAT FS=NTFS QUICK LABEL="Tools" on that selected partition;
its confirmation includes PARTITION n. ASSIGN LETTER=X mounts it.
For existing NTFS: SELECT PARTITION n, SHRINK QUERYMAX, then either
SHRINK DESIRED=MB or EXTEND SIZE=MB with their explicit confirmations.
The installation preset's fixed sizes do not limit free R4PART choices.
No extended/logical MBR, partition MOVE, RAID or virtual disks are provided.
